**Headline finding:** this task is **structurally unsolvable under the benchmark's information regime**, independent of any mined context. The human PR regenerated the VCR test fixtures with a **fresh random EC key** (fixture timestamps `2021-08-24T16:41:26+02:00` — the day of the PR); those fixtures live in the *hidden* test patch, while the matching `testKID` constant lives in a *source* file (`vcr/test.go`) that the agent must edit. No agent can guess a random key's DID/thumbprint. 0/10 is a benchmark-construction artifact, not a context-mining failure — though the upstream-context story underneath is still instructive.

## Step 1 — The breaking change and its repair facts

Ground truth (`solution/code.patch`, 3 files) + hidden tests (`tests/test.patch`, 8 files, 159 lines):

| # | Repair fact | Where in ground truth | Surfaced by compiler? |
|---|---|---|---|
| **F1** | `jwt.Sign` in v1.2 takes `...jwt.SignOption`; `jws.WithHeaders(hdr)` (now typed `jws.SignOption` since v1.2.2) no longer accepted → replace with `jwt.WithHeaders(hdr)` | `crypto/jwx.go:105` (1 line) | **Yes** — `cannot use jws.WithHeaders(hdr) (type jws.SignOption) as type jwt.SignOption` |
| **F2** | RFC 7797 (v1.2.5): with header `b64:false`, `jws.Sign` now signs the **raw** payload (previously always base64url-encoded it) and **rejects** payloads containing `.` — `jws/message.go:87` at v1.2.6: `` `payload must not contain a "." when b64 = false` ``. nuts-node's JsonWebSignature2020 challenge (concatenated raw SHA-256 sums) can contain `.`. Human fix: pre-encode the challenge with `base64.RawURLEncoding` before signing (`generateCredentialChallenge` / `generateRevocationChallenge` in `vcr/vcr.go`), and drop the extra `EncodeToString` in the two `Verify` paths so the verification input `hdr + "." + payload` stays byte-identical to v1.1-era signatures (wire compatibility preserved) | `vcr/vcr.go` (4 hunks) | **No** — silent behavioral change; only fails at runtime, and only for payloads that happen to contain `0x2E` |
| **F3** | Regenerated test key + fixtures: new `private.pem`, `public.json` (old fixture had **padded std-base64** EC coordinates, e.g. `"x":"96KYea8...IBg="`; new one has spec-correct raw base64url — v1.1 tolerated the malformed JWK, v1.2 is strict), new signatures in `vc.json`/`revocation.json`, new DID `did:nuts:CuE3qeFGGLhEAS3gKzhMCeqd1dGa9at5JCbmCfyMU2Ey` in `issuers.yaml`, `trust_test.go`, `common_test.go` — and the matching constant in **source**: `vcr/test.go` `testKID = "did:nuts:CuE3qeF...#sNGDQ3NlOe6Icv0E7_ufviOLG6Y25bSEyS5EbXBgp8Y"` | `vcr/test.go` (source) + 6 hidden fixture/test files | **No** — value is a function of a random key generated by the PR author on 2021-08-24 |

### Why the 8-file hidden-test surface kills partial fixes

`tests/test_state.py` applies `test.patch` **only at grading** ("the agent never sees it during its own session"), then runs `go test ./crypto/... ./vcr/... ./network/p2p/... ./vdr/types/...`. The unhidden `vcr/vcr_test.go` builds mock expectations from the `testKID` constant, while `vcr.go` extracts the kid from the (now hidden-new) fixture's `proof.verificationMethod`. Any repair keeping the old `testKID` produces gomock mismatches:

```
Got:  did:nuts:CuE3qeFGGLhEAS3gKzhMCeqd1dGa9at5JCbmCfyMU2Ey#sNGDQ3NlOe6Icv0E7_ufviOLG6Y25bSEyS5EbXBgp8Y
Want: is equal to did:nuts:t1DVVAs5fmNba8fdKoTSQNtiGcH49vicrkjZW2KRqpv#h22vbXHX7-lRd1qAJnU63liaehb9sAoBS7RavhvfgR8
```

Perversely, the *agent-visible* repo (old fixtures) gives the opposite signal: with old fixtures, **the tests pass without F2 or F3 at all** (both claude48 configs got a fully green local run with only the F1 one-liner — the old fixtures' payload hashes happen not to contain `.`). The oracle `code.patch`, conversely, would *fail* against the visible fixtures. The local test oracle is anti-correlated with the graded oracle.

Only theoretical escape route: rewrite `vcr/test.go` to *derive* `testKID` at runtime from `vcr/test/public.json` (nuts DIDs and kid fragments are deterministic functions of the public key — base58/JWK-thumbprint), so the hidden fixture swap is tracked automatically. This requires the agent to (a) anticipate that grading swaps fixtures and (b) reimplement DID derivation — no agent tried, and nothing in the task instruction hints at it.

## Step 2 — What agents actually did (gap vs ground truth)

All 10 configs: reward 0. Verifier tails (`verify_logs/*.jsonl.gz`) split into exactly two failure signatures, both inside `vcr` with hidden fixtures applied:

- **8/10** (`*__claude_code`, `*__opencode`, `gpt55__codex`, `gpt55__copilot_cli`): the `testKID` gomock mismatch above (`TestVcr_verifyRevocation/...`, `vcr_test.go:990/1012`). Includes `gemini35flash__opencode` which also hit `AgentTimeoutError`.
- **2/10** (`claude48__copilot_cli`, `gemini35flash__copilot_cli`): earlier abort — `TestVcr_Issue` panics (`vcr_test.go:328`, nil deref after `Issue` errors; mock `CreateTransaction` never called). These agents made only the F1 fix; under the new fixtures the F2 signing path (`b64=false`, dot-containing challenge) errors during issuance, killing the test binary before reaching the kid mismatches.

Trajectory detail:

- **gpt55__copilot_cli** — best run. Bumped, compiled, fixed F1 (used `jwt.WithJwsHeaders`); then *independently rediscovered F2 from the vendored upstream source*: "The remaining deterministic regression is jws signing with `b64=false`; jwx 1.2.6 now rejects compact serialization for payloads containing dots" and implemented a source-only detached-JWS path in `crypto/jwx.go`. Full local suite green. **Failed grading anyway** on F3.
- **claude48__claude_code** — bumped, `go mod tidy`, fixed F1 with exactly the ground-truth line (`jwt.WithHeaders(hdr)`), ran the full suite: green (old fixtures don't exercise F2). Diligently proved the one flaky network-integration failure was pre-existing by re-running on v1.1.2. Declared done with a 1-line source diff. **Failed grading** on F3 (and latently F2).

**Gap statement:** the compiler surfaced F1 for everyone; F2 was discoverable (one agent found it, others weren't forced to because the visible fixtures gave a false green); **F3 is not discoverable by any means** — it is a random value minted by the human author after the cutoff, sitting on the hidden side of the test split.

## Step 5 — Verdict

**Knowability matrix:**

| Fact | Upstream docs | Upstream code/tests | Siblings | Local compiler/tests | Nowhere |
|---|---|---|---|---|---|
| F1 `jwt.Sign` options | ~ (v1.2.2 note, oblique) | ✓ (godoc `jwt.WithHeaders`) | ✗ | ✓ (compile error names both types) | |
| F2 RFC7797 b64 | ✓ (v1.2.5 Changes, explicit) | ✓ (PR #419, error string, Sign doc) | ✗ | ~ (visible fixtures don't trip it; graded ones do) | |
| F3 new key/DID/kid + fixtures | ✗ | ✗ | ✗ | ✗ | **✓ — random value minted post-cutoff, hidden split** |

**Sibling stratum:** long-tail. 8 repos crossed 1.1→1.2 pre-cutoff (38 merged v1.2-era bumps, 36 repos ever); exactly **1** sibling source repair, covering a disjoint (jwk-side) fact set. Uniform Dependabot titling makes recall trivial, but yield here is ~nil: for a moderately popular library, three months after a breaking minor, almost every earlier adopter either didn't touch the broken surface or was on an unaffected path. Lesson for the long-tail regime: when siblings are few, they sample the *common* API surfaces (JWKS fetch/verify), not the exotic ones (RFC7797 detached signing of W3C VC proofs) — the more idiosyncratic the client, the less transferable sibling evidence exists.

**Minimal context artifact that would have flipped the task:** none exists within the rules. The observed binding failure in 10/10 runs traces to F3. A perfect mined-context bundle (v1.2.5 changelog lines + jwx#419 diff + the tweek hunks) upgrades the *modal* agent repair from "F1 only, false-green locally" to "F1+F2, semantically equal to the human's non-fixture changes" — worth it in a counterfactual benchmark where fixtures weren't regenerated — but grading would still return 0. The only flip levers are benchmark-side: (a) include `vcr/test.go` + fixtures on the same side of the hidden/visible split; (b) or grade on a test subset independent of the regenerated key; (c) or accept behavioral equivalence rather than the human's exact fixture set.

**Surprises:**
1. The **anti-correlated oracle**: the agent-visible test suite passes with a 1-line fix and *fails* under the ground-truth patch; the graded suite inverts both. Agents that "verified" hardest (claude48 even bisected a flaky test against v1.1.2) were most confidently wrong.
2. gpt-5.5 rediscovered the RFC7797 change *from the module cache* (`/go/pkg/mod/...jwx@v1.2.6` source + upstream's own tests) without any web access — upstream-code-as-context works even offline.
3. The Dependabot PR body itself carried the key changelog lines ("Implement RFC7797...") — the cheapest imaginable context artifact was already in the task's provenance.
4. The root cause of the fixture regeneration is itself an undocumented strictness change (v1.1 emitted/accepted padded std-base64 JWK coordinates; v1.2 does not) — even a perfect changelog reader wouldn't predict the old `public.json` was malformed.

**Facts even perfect mining wouldn't surface:** the new EC private key, its DID (`did:nuts:CuE3qeF...`) and JWK thumbprint (`sNGDQ3...`), the fixture signatures/timestamps — all generated by the PR author hours after the cutoff and shipped only in the hidden test patch.

**Classification for the research question:** *not-context-limited; harness-limited.* Exclude from (or specially annotate in) aggregate "could mined context have fixed it" statistics; it is a clean specimen of the "human repair entangles source constants with regenerated test data" hazard for hidden-test benchmark construction.
